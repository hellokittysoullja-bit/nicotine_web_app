# Knowledge Hub Recipe

## User Job

Find the right answer quickly, understand where it belongs, and move confidently to a related task or deeper explanation.

## Fast or Capability Path

Use the fast path for a small static collection with stable navigation, manually maintained search or index pages, and no authentication. Use the capability path for full-text search, many routes, content management, versions, localization, role-based access, feedback workflows, or generated reference content.

## Recommended Structure

1. Hub home with clear scope, search, and top tasks.
2. Audience-centered categories rather than internal organizational labels.
3. Featured, popular, or recently relevant entry points when evidence supports them.
4. Article layout with breadcrumb, local navigation, clear title, summary, and owner.
5. Optional table of contents for long pages.
6. Related content and next-task links.
7. Feedback, correction, or contact path.
8. Helpful not-found and search-empty experiences.

## Content and Data Needs

- taxonomy, category owners, and navigation labels;
- article title, summary, body, owner, status, version or applicability when relevant;
- stable identifiers, slugs, aliases, and redirects;
- search terms, synonyms, glossary, and expected top queries;
- code, downloads, screenshots, and their maintenance owners;
- update and retirement policy;
- access rules for restricted material;
- feedback destination and response ownership.

## Visual Traps

- oversized marketing hero that delays search or navigation;
- dashboard chrome around simple reading tasks;
- categories based on internal team structure instead of user intent;
- excessive card grids with ambiguous labels;
- very wide reading columns or weak heading contrast;
- sidebars that consume the phone viewport or obscure content;
- stale update badges that imply reliability without ownership.

## Interactions and States

Test global and local navigation, search suggestions, results, no results, filters, in-page anchors, code copying, downloads, feedback, redirects, restricted content, and not-found routes. Dynamic search requires loading, failure, keyboard selection, clearing, and preserved query state where useful.

## Responsive and Accessibility Checks

- Search and top tasks remain prominent at every size.
- Side navigation becomes an accessible drawer or inline index with predictable focus.
- Breadcrumbs and article identity remain visible after navigation collapses.
- Code, tables, diagrams, and long tokens have deliberate overflow behavior.
- Deep links and heading anchors work after refresh.
- Search controls have labels and status announcements.
- Reading measure, text zoom, and keyboard order remain comfortable.

## Done Criteria

- [ ] Representative user questions map to obvious navigation or successful search results.
- [ ] Article ownership, applicability, and update expectations are clear.
- [ ] Search covers results, empty, error, clear, and keyboard states.
- [ ] Navigation and deep links work on desktop and phone.
- [ ] Long-form content, code, tables, and downloads remain accessible.
- [ ] Broken, moved, restricted, and retired content have intentional outcomes.
- [ ] The hub can be maintained without relying on hidden agent knowledge.
