# Lean context

Экономим объём того, что тянется в контексте, а не проверки. Рендер, axe, ревью агентов и замеры остаются обязательными.

## Чтение
- Сначала `grep -n` по нужному месту, потом `Read` с `offset`/`limit`. Файл целиком — только если нужен целиком.
- После Edit файл не перечитывать: инструмент упал бы, если правка не прошла.
- Не читать то, что уже записано в `docs/HANDOFF.md`.

## Скриншоты
- Открывать только кадр, который отвечает на вопрос: первый экран и одна проблемная секция.
- Полную страницу резать на части (PIL) и смотреть только нужные куски.
- Размеры, позиции, цвета — числами через `getBoundingClientRect` / `getComputedStyle` в Playwright, а не ещё одним снимком.

## Субагенты
- В задании ставить объём отчёта: «до 600 слов, только дефекты с фиксом и местом в коде».
- Сразу сводить отчёт в 5–10 строк решений в `docs/HANDOFF.md`.

## Вывод команд
- Резать вывод: `| tail -n 5`, `| head`, `grep`.
- Скрипты проверки печатают одну строку итога, например «errors: none».

## Правки
- Точечный Edit или короткий python-replace с `assert` на совпадение.
- В ответ пользователю код не дублировать: код и есть результат.

## Состояние на диске
После каждого крупного шага обновлять `docs/HANDOFF.md`:
- цель пользователя;
- рабочий файл;
- что сделано;
- что осталось по приоритету;
- принятые решения;
- команды проверки.

Файл должен читаться без истории разговора.

## Перед /compact
1. Обновить `docs/HANDOFF.md`.
2. Закоммитить и запушить, если пользователь разрешил.
3. Сказать пользователю, что можно вводить `/compact`. Это команда интерфейса, сам агент её не вызывает.
4. После сжатия первым делом прочитать `docs/HANDOFF.md`.
